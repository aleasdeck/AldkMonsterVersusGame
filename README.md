# Monster Versus

Пошаговый пиксельный рогалик в браузере. Шесть локаций, за забег три случайные по десять клеток (семь боёв и три случайных события: торговец, сундук, алтарь, привал, кузнец или засада элиты), шесть героев с разным владением ближним, дальним и магическим оружием и умением носить тяжёлую, среднюю или лёгкую броню, 15 баз оружия и 7 баз брони со своими перками и характеристиками (тяжёлая броня — защита, лёгкая — почти без неё; стилет бьёт слабее меча, топор — сильнее; перк работает только у героя, который владеет типом оружия и умеет носить тип брони, чужое оружие вдобавок бьёт вполовину кубика), слоты под артефакты в каждом предмете (на старте один персональный артефакт героя, который выпадает только ему), намерения врагов как в Slay the Spire. Золото за бои тратится на переброс награды, у торговца (лекарь, случайная экипировка, случайный артефакт, зелье) и у кузнеца (тир оружия или брони +1). У героя один слот под зелье: зелья с шансом 10 % падают с монстров и пьются в бою бесплатно. За каждый забег дают сундук с находкой в коллекцию. Дизайн-документ — в `docs/GDD.md`.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # vitest, тесты движка
SIM=1 npx vitest run tests/balance-sim.test.ts   # бот-симулятор баланса: победы, смерти, приёмы и зелья по героям
SIM=1 SIM_HERO=berserk SIM_N=300 npx vitest run tests/balance-sim.test.ts   # один герой, своё число забегов
SIM_DEBUG=1 SIM_HERO=warrior SIM_SEED=3 SIM_FIGHTS=4 npx vitest run tests/sim-debug.test.ts   # лог первых боёв бота: что и почему он делает
SIM_DEBUG=stall SIM_HERO=paladin npx vitest run tests/sim-debug.test.ts   # найти забег с патом и показать хвост зависшего боя
npm run build      # typecheck + сборка в dist/
npm run preview    # посмотреть собранную версию
```

Собранная версия — статика. Каждый пуш в `main` выкладывает её на GitHub Pages (`.github/workflows/pages.yml`): **https://aleasdeck.github.io/AldkMonsterVersusGame/** — отладочные параметры URL работают и там.

Какая версия игры открыта, видно в правом нижнем углу главного меню (например, «v0.19.1») — там же её стоит смотреть перед тем, как сообщать о баге.

## Управление

Кадр забега: сверху топбар (кнопка ☻ — оверлей «Персонаж», золото, акт и локация, лента из десяти клеток этажа, ход, таймер забега, меню), в центре поле боя или карточки, снизу консоль с блоком героя (HP, STA, MP, зелье), плитками приёмов и «Концом хода». Наведение на плитку показывает описание в строке над плитками и штрихует на полоске цели, сколько HP у неё останется. Наведение на предмет в награде или у торговца подсвечивает плитку экипировки в консоли и показывает дельты замены. Приёмы в бою анимированы типовыми эффектами: взмах клинком, стрела, магический снаряд, склянка, облако дебафа и свечение бафа; блок показан наложением на полоске HP.

Горячие клавиши: `1`–`9` — приёмы по порядку плиток, `Space` — конец хода, `C` — персонаж, `L` — лог боя (все бои забега, работает и на итогах), `Esc` — закрыть верхний слой или открыть паузу. В паузе — сид с копированием, выход в меню с сохранением, «Бросить забег».

## Отладочные параметры URL

- `?screen=select|collection|bestiary|chest|spin` — экран выбора героя, коллекция, бестиарий, сундук или сразу прокрутка сундука; `&screen=bestiary&loc=crypt` — вкладка нужной локации.
- `&mock=1` — залить демо-профиль: статистика, три сундука, часть коллекции и половина бестиария.
- `?hero=warrior&seed=5` — новый забег указанным героем (`warrior`, `mage`, `paladin`, `berserk`, `archer`, `assassin`) с заданным сидом.
- `&enter=1` — сразу войти в первую комнату.
- `&phase=won|reward|shop|event|camp|end` — сразу нужный экран (бой выигрывается читом); `&phase=won` — остаться на плашке победы, `&log=1` — с раскрытым логом боя; `&phase=shop` и `&phase=camp` — торговец или привал в клетке события; `&phase=event&event=chest|altar|forge|elite|shop|camp` — заданное событие (без `event` — случайное); `&phase=reward&take=art` — сразу взять артефакт из награды и открыть выбор слота; `&room=9&phase=reward` — трофей босса (`&room=N` — начать с клетки 0..9).
- `&sheet=1` — открыть оверлей «Персонаж», `&pause=1` — паузу (на любом экране забега).
- `&locs=swamp,hive,ship` — задать локации забега по порядку (`forest`, `swamp`, `crypt`, `hive`, `caves`, `ship`); `&loc=1` — начать с акта 0..2; `&art=second_wind,stun_strike` — досыпать артефакты в оружие; `&use=war_cry` — применить их сразу после входа в бой; `&potion=heal_potion` — положить зелье в слот (`heal_potion`, `strength_potion`, `stamina_potion`, `mana_potion`, `stone_skin`, `fire_flask`, `antidote`).

В консоли браузера доступен объект `mv` (экземпляр `App`): `mv.run` — состояние забега, `mv.render()` — перерисовать.

## Структура

```
src/
  engine/      чистая логика без DOM, покрыта тестами
    types.ts     все типы данных
    rng.ts       детерминированный PRNG (mulberry32)
    stats.ts     расчёт статов героя из базы, экипировки и пассивок
    combat.ts    бой: ходы, действия, статусы, ИИ врагов, намерения
    equipment.ts слоты, вставка и апгрейд артефактов, смена экипировки
    loot.ts      генерация наград, товаров и событий
    run.ts       машина состояний забега: комнаты, события, награды
  data/        герои, враги, артефакты, зелья, экипировка, локации
  ui/          DOM-рендер: frame/topbar/console — каркас забега, screens/ — экраны, tooltip/keywords/preview/diff — подсказки и предпросмотры, fx — анимации боя, hotkeys, спрайты, сохранение
tests/         vitest; sim/bot.ts — бот-симулятор: планирует ход перебором на копии состояния, вне боя считает ценность предметов
docs/GDD.md    дизайн-документ
```

Сохранение забега — в `localStorage`, обновление страницы не сбрасывает прогресс. Сид показан в паузе (`Esc`) и на экране итогов: один и тот же сид с тем же героем даёт тот же забег.
