# Monster Versus

Пошаговый пиксельный рогалик в браузере. Шесть локаций, за забег три случайные по семь комнат, шесть героев с разным владением ближним, дальним и магическим оружием, 14 баз оружия и 6 баз брони со своими перками, слоты под артефакты в каждом предмете, намерения врагов как в Slay the Spire. Золото за бои тратится на переброс награды. За каждый забег дают сундук с находкой в коллекцию. Дизайн-документ — в `docs/GDD.md`.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # vitest, тесты движка
SIM=1 npx vitest run tests/balance-sim.test.ts   # бот-симулятор баланса: победы, смерти и приёмы по героям
SIM=1 SIM_HERO=berserk SIM_N=100 npx vitest run tests/balance-sim.test.ts   # один герой, своё число забегов
npm run build      # typecheck + сборка в dist/
npm run preview    # посмотреть собранную версию
```

Собранная версия — статика, её можно выложить на любой хостинг (GitHub Pages, Netlify).

## Отладочные параметры URL

- `?screen=select|collection|chest|spin` — экран выбора героя, коллекция, сундук или сразу прокрутка сундука.
- `&mock=1` — залить демо-профиль: статистика, три сундука и часть коллекции.
- `?hero=warrior&seed=5` — новый забег указанным героем (`warrior`, `mage`, `rogue`, `paladin`, `berserk`, `archer`) с заданным сидом.
- `&enter=1` — сразу войти в первую комнату.
- `&phase=reward|event|camp|end` — сразу нужный экран (бой выигрывается читом); `&phase=reward&take=art` — сразу взять артефакт из награды и открыть выбор слота.
- `&locs=swamp,hive,ship` — задать локации забега по порядку (`forest`, `swamp`, `crypt`, `hive`, `caves`, `ship`); `&loc=1` — начать с акта 0..2; `&art=second_wind,stun_strike` — досыпать артефакты в оружие; `&use=war_cry` — применить их сразу после входа в бой.

В консоли браузера доступен объект `mv` (экземпляр `App`): `mv.run` — состояние забега, `mv.render()` — перерисовать.

## Структура

```
src/
  engine/      чистая логика без DOM, покрыта тестами
    types.ts     все типы данных
    rng.ts       детерминированный PRNG (mulberry32)
    stats.ts     расчёт статов героя из базы, экипировки и пассивок
    combat.ts    бой: ходы, действия, статусы, ИИ врагов, намерения
    equipment.ts слоты, вставка и апгрейд артефактов, смена экипировки
    loot.ts      генерация наград и событий
    run.ts       машина состояний забега: комнаты, награды, привал
  data/        герои, враги, артефакты, экипировка, локации
  ui/          DOM-рендер: экраны, компоненты, процедурные спрайты, сохранение
tests/         vitest
docs/GDD.md    дизайн-документ
```

Сохранение забега — в `localStorage`, обновление страницы не сбрасывает прогресс. Сид показывается на каждом экране: один и тот же сид с тем же героем даёт тот же забег.
