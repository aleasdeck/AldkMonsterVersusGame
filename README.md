# Monster Versus

Пошаговый пиксельный рогалик в браузере. Шесть локаций, за забег три случайные по десять клеток (семь боёв и три случайных события: торговец, сундук, алтарь, привал, кузнец или засада элиты), шесть героев с разным владением ближним, дальним и магическим оружием и умением носить тяжёлую, среднюю или лёгкую броню, 16 баз оружия и 7 баз брони со своими перками и характеристиками (тяжёлая броня — защита, лёгкая — почти без неё; стилет бьёт слабее меча, топор — сильнее; перк работает только у героя, который владеет типом оружия и умеет носить тип брони, чужое оружие вдобавок бьёт вполовину кубика), слоты под артефакты в каждом предмете (на старте один персональный артефакт героя, который выпадает только ему), намерения врагов как в Slay the Spire. Ближний бой достаёт только первого в ряду, дальнее и магическое оружие, копьё и заклинания — любого врага, плеть хлещет весь ряд, Крюк-кошка притягивает врага под удар (v0.26). Золото за бои тратится на переброс награды, у торговца (лекарь, случайная экипировка, случайный артефакт, зелье) и у кузнеца (тир оружия или брони +1). У героя один слот под зелье: зелья с шансом 10 % падают с монстров и пьются в бою бесплатно. Всё, что достаётся герою в забеге, открывается в коллекции — артефакты с точностью до тира. Дизайн-документ — в `docs/GDD.md`.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # vitest, тесты движка
SIM=1 npx vitest run tests/balance-sim.test.ts   # бот-симулятор баланса: победы, смерти, приёмы и зелья по героям
SIM=1 SIM_LOCS=caves,caves,caves SIM_N=200 npx vitest run tests/balance-sim.test.ts   # один босс на всех трёх актах
SIM=1 SIM_HERO=berserk SIM_N=300 npx vitest run tests/balance-sim.test.ts   # один герой, своё число забегов
SIM_DEBUG=1 SIM_HERO=warrior SIM_SEED=3 SIM_FIGHTS=4 npx vitest run tests/sim-debug.test.ts   # лог первых боёв бота: что и почему он делает
SIM_DEBUG=stall SIM_HERO=paladin npx vitest run tests/sim-debug.test.ts   # найти забег с патом и показать хвост зависшего боя
npm run build      # typecheck + сборка в dist/
npm run preview    # посмотреть собранную версию
```

Собранная версия — статика. Каждый пуш в `main` выкладывает её на GitHub Pages (`.github/workflows/pages.yml`): **https://aleasdeck.github.io/AldkMonsterVersusGame/** — отладочные параметры URL работают и там.

С v0.27 игра на Pages отправляет анонимную статистику каждого законченного или брошенного забега (герой, версия, снаряжение и артефакты, локации, урон, время) в Google Таблицу — без имён, адресов и прочих личных данных; с localhost ничего не отправляется, забеги с отладочными параметрами помечены как отладочные. Что именно уходит, как завести свою таблицу и куда вставить её адрес — `docs/statistika.md`.

Какая версия игры открыта, видно в правом нижнем углу главного меню (например, «v0.19.1») — там же её стоит смотреть перед тем, как сообщать о баге.

## Управление

Кадр забега: сверху топбар (кнопка ☻ — оверлей «Персонаж», золото, акт и локация, лента из десяти клеток этажа, ход, таймер забега, меню), в центре поле боя или карточки, снизу консоль с блоком героя (HP, STA, MP, зелье), плитками приёмов и «Концом хода». В бою сначала выбирается приём, потом цель: клик по плитке выбирает приём (он остаётся выбранным, пока его можно применить), клик по врагу применяет; приёмы на себя и по всем применяются сразу. У оружия на карточке и плитке — маркер дальности: три точки, ближнее оружие красит первую (достаёт только первого в ряду), дальнее, магическое, копьё и плеть — все три. Наведение на плитку показывает описание в строке над плитками и подсвечивает врагов, которых приём достанет; наведение на врага с выбранным приёмом пишет, сколько HP у него останется, и штрихует это на полоске. Наведение на предмет в награде или у торговца подсвечивает плитку экипировки в консоли и показывает дельты замены. Приёмы в бою анимированы типовыми эффектами: взмах клинком, стрела, магический снаряд, склянка, облако дебафа и свечение бафа; блок показан наложением на полоске HP. Босс на половине HP переходит во вторую фазу: вспышка, всплывающее название и постоянная аура на враге; Лич и Капитан вместо этого встают после смерти новым телом.

Горячие клавиши: `1`–`9` — приёмы по порядку плиток (выбрать; номер уже выбранного — применить к цели), `Enter` — применить выбранный приём к цели (`Tab` перебирает цели), `Space` — конец хода, `C` — персонаж, `L` — лог боя (все бои забега, работает и на итогах), `Esc` — снять выбор приёма, закрыть верхний слой или открыть паузу. В паузе — сид с копированием, выход в меню с сохранением, «Бросить забег».

## Отладочные параметры URL

- `?screen=select|collection|bestiary|stats` — экран выбора героя, коллекция, бестиарий или статистика; `&screen=bestiary&loc=crypt` — вкладка нужной локации; `&screen=stats&mock=1` — статистика на демо-ответе таблицы, без сети.
- `&mock=1` — залить демо-профиль: статистика, часть коллекции (у артефактов открыта часть тиров) и половина бестиария.
- `?hero=warrior&seed=5` — новый забег указанным героем (`warrior`, `mage`, `paladin`, `berserk`, `archer`, `assassin`) с заданным сидом.
- `&enter=1` — сразу войти в первую комнату; `&room=9&enter=1&boss2=1` — бой с боссом сразу во второй фазе (HP на порог и один удар героя; у Лича и Капитана — сразу второе тело).
- `&phase=won|reward|shop|event|camp|end` — сразу нужный экран (бой выигрывается читом); `&phase=won` — остаться на плашке победы, `&log=1` — с раскрытым логом боя; `&phase=shop` и `&phase=camp` — торговец или привал в клетке события; `&phase=event&event=chest|altar|forge|elite|shop|camp|gnome|gnome_art` — заданное событие (без `event` — случайное; `gnome` и `gnome_art` сразу начинают бой с вором: деньгокрадом или вещекрадом); `&events=<вид>` — то же, но на весь забег: каждая клетка события разыгрывает заданный вид (живой забег, гарантированное событие); `&phase=reward&take=art` — сразу взять артефакт из награды и открыть выбор слота; `&room=9&phase=reward` — трофей босса (`&room=N` — начать с клетки 0..9).
- `&gauntlet=1` — парад боссов: каждый акт начинается сразу с босса, экипировка героя на 5 тире, артефакты из `&art=` на 3-м, HP полное; трёх боссов задаёт `&locs=`, остальных трёх — второй забег.
- `&sheet=1` — открыть оверлей «Персонаж», `&pause=1` — паузу (на любом экране забега).
- `&locs=swamp,hive,ship` — задать локации забега по порядку (`forest`, `swamp`, `crypt`, `hive`, `caves`, `ship`); `&loc=1` — начать с акта 0..2; `&art=second_wind,stun_strike` — досыпать артефакты в оружие (в универсальные сокеты, тип артефакта не важен); `&use=war_cry` — применить их сразу после входа в бой; `&potion=heal_potion` — положить зелье в слот (`heal_potion`, `strength_potion`, `stamina_potion`, `mana_potion`, `stone_skin`, `fire_flask`, `antidote`).
- `&stats=1` — отправить статистику забега и с localhost (проверить таблицу; запись помечается debug). Пока адрес таблицы в `src/ui/telemetry.ts` пустой, не отправляется ничего.

В консоли браузера доступен объект `mv` (экземпляр `App`): `mv.run` — состояние забега, `mv.render()` — перерисовать.

## Структура

```
src/
  engine/      чистая логика без DOM, покрыта тестами
    types.ts     все типы данных
    rng.ts       детерминированный PRNG (mulberry32)
    stats.ts     расчёт статов героя из базы, экипировки и пассивок
    combat.ts    бой: ходы, действия, статусы, ИИ врагов, намерения
    equipment.ts слоты и их типы (оружейный / бронный / универсальный), вставка и апгрейд артефактов, смена экипировки
    loot.ts      генерация наград, товаров и событий
    run.ts       машина состояний забега: комнаты, события, награды
    report.ts    запись статистики забега: поле — колонка таблицы
  data/        герои, враги, артефакты, зелья, экипировка, локации
  ui/          DOM-рендер: frame/topbar/console — каркас забега, screens/ — экраны, tooltip/keywords/preview/diff — подсказки и предпросмотры, fx — анимации боя, hotkeys, спрайты, сохранение, telemetry — отправка статистики забегов
tests/         vitest; sim/bot.ts — бот-симулятор: планирует ход перебором на копии состояния, вне боя считает ценность предметов
docs/GDD.md    дизайн-документ
docs/statistika.md         статистика забегов: что уходит, как подключить таблицу
tools/apps-script/Code.gs  приёмник статистики для Google Таблицы
```

Сохранение забега — в `localStorage`, обновление страницы не сбрасывает прогресс. Сид показан в паузе (`Esc`) и на экране итогов: один и тот же сид с тем же героем даёт тот же забег.
