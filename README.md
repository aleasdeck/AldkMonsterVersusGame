# Monster Versus

Пошаговый пиксельный рогалик в браузере. Три локации по пять комнат, пять героев, оружие и броня со слотами под артефакты, намерения врагов как в Slay the Spire. Дизайн-документ — в `docs/GDD.md`.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # vitest, тесты движка
npm run build      # typecheck + сборка в dist/
npm run preview    # посмотреть собранную версию
```

Собранная версия — статика, её можно выложить на любой хостинг (GitHub Pages, Netlify).

## Отладочные параметры URL

- `?screen=select` — сразу экран выбора героя.
- `?hero=warrior&seed=5` — новый забег указанным героем (`warrior`, `mage`, `rogue`, `paladin`, `berserk`) с заданным сидом.
- `&enter=1` — сразу войти в первую комнату.
- `&phase=reward|event|camp|end` — сразу нужный экран (бой выигрывается читом).
- `&loc=1` — начать с локации 0..2; `&art=second_wind,stun_strike` — досыпать артефакты в оружие; `&use=war_cry` — применить их сразу после входа в бой.

В консоли браузера доступен объект `mv` (экземпляр `App`): `mv.run` — состояние забега, `mv.render()` — перерисовать.

## Структура

```
src/
  engine/      чистая логика без DOM, покрыта тестами
    types.ts     все типы данных
    rng.ts       детерминированный PRNG (mulberry32)
    stats.ts     расчёт статов героя из базы, экипировки и пассивок
    combat.ts    бой: ходы, действия, статусы, ИИ врагов, намерения
    equipment.ts слоты, вставка и апгрейд артефактов, смена экипировки
    loot.ts      генерация наград и событий
    run.ts       машина состояний забега: комнаты, награды, привал
  data/        герои, враги, артефакты, экипировка, локации
  ui/          DOM-рендер: экраны, компоненты, процедурные спрайты, сохранение
tests/         vitest
docs/GDD.md    дизайн-документ
```

Сохранение забега — в `localStorage`, обновление страницы не сбрасывает прогресс. Сид показывается на каждом экране: один и тот же сид с тем же героем даёт тот же забег.
