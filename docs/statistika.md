# Статистика забегов

С v0.27 собранная игра на GitHub Pages отправляет одну запись о каждом законченном или брошенном забеге в Google Таблицу. Цель — видеть, кем и как проходят игру живые люди: на каком герое, в какой версии, с каким снаряжением, где гибнут, сколько наносят и получают урона, сколько длится забег.

Цепочка: `src/engine/report.ts` собирает запись из состояния забега (чистая функция, покрыта тестами в `tests/run.test.ts`) → `src/ui/telemetry.ts` решает, слать ли, и шлёт POST → `tools/apps-script/Code.gs` внутри таблицы дописывает строку в лист `runs`.

## Что уходит

Одна запись — одна строка, поле — колонка. Первая колонка `ts` — время приёма, её ставит скрипт.

| Поле | Что это |
|---|---|
| `event` | `victory`, `defeat` или `abandoned` (брошен) |
| `version` | версия игры из меню, `GAME_VERSION` |
| `debug` | отладочный забег (`?hero=…`) или отправка с машины разработчика по `&stats=1` |
| `player`, `playerRuns` | анонимный id игрока (случайная строка в профиле) и сколько забегов он закончил до этого |
| `hero`, `seed` | герой и сид |
| `phase` | фаза в момент записи: у брошенного — где бросили (`map`, `battle`, `shop`…) |
| `act`, `location`, `room`, `roomKind` | акт 1..3, локация, клетка 1..10 и её вид; внутри события — `event:shop` и т. п.; победа — акт 3, клетка 10, `boss` |
| `locations` | три локации забега по порядку |
| `roomsCleared`, `kills`, `turns` | боёв выиграно, врагов убито, ходов |
| `damageDealt`, `damageTaken` | урон нанесён и получен |
| `duration` | секунды от старта до конца по часам, как таймер в топбаре; у брошенного — до момента записи |
| `gold`, `hp`, `maxHp` | золото и HP в момент записи |
| `weapon`, `armor` | база и тир, аффикс через плюс: `sword@3 +crit` |
| `artifacts` | все артефакты в сокетах с тирами через пробел: `fireball@2 whirlwind@1` |
| `potion` | зелье в слоте |
| `lastBattle`, `battles` | заголовок последнего боя (при гибели — кто убил) и число боёв |
| `touch`, `screen`, `lang` | тач или мышь, размер окна, язык браузера |
| `detail` | JSON: снаряжение как есть (имена, цифры, слоты), статистика, список боёв с исходом (`won`, `lost`, `fled` — вор удрал) и числом ходов — без строк лога |

Ничего личного нет: ни имён, ни адресов, ни user agent. Адрес отправителя видит Google, как при любом запросе, но в таблицу он не пишется.

## Когда уходит и когда нет

- **Гибель** — в тот момент, когда герой пал, ещё на плашке «Герой пал», не дожидаясь кнопки «К итогам» (`App.noteOutcome()`). Нажмут кнопку, перезагрузят страницу, уйдут в меню или закроют вкладку — запись уже отправлена, и второй не будет: отметка `RunState.reported` лежит в сохранении забега. До v0.30.2 гибель отправляла только кнопка «К итогам», поэтому закрытая на плашке вкладка не оставляла о забеге ни строчки.
- **Победа** — когда забег переходит в фазу `victory`, то есть после трофея с финального босса (там же, где результат пишется в профиль).
- **Брошенный забег** — когда поверх незаконченного начинают новый (выбор героя, `?hero=`) или жмут «Бросить забег» в паузе. Забег, который просто закрыли и не открывали больше, не виден: он так и лежит в сохранении — но если герой в нём успел пасть, запись уйдёт сама при следующем запуске игры.
- **Незакрытый бой попадает в запись**: его ходы, убийства и урон прибавляются к цифрам забега, заголовок идёт в `lastBattle`, а в `detail.battles` он ложится последним — с исходом `lost` у гибели и `unfinished` у забега, брошенного посреди боя.
- **Одна запись на забег** по каждому исходу: отправка помечает забег, так что гибель не задваивается и не приходит второй раз как `abandoned`.
- **Ретраев нет**: одна попытка `fetch`, ответ не читается, ошибка сети глотается — запись теряется молча. Если это начнёт мешать, следующий шаг — очередь в localStorage с досылкой при следующем запуске.
- **Не уходит** с dev-сервера, с `localhost`, `127.*`, `[::1]` и из домашней сети (`10.*`, `192.168.*`, `172.16–31.*`) — чтобы отладка не портила цифры. Исключение — параметр `&stats=1`: запись уходит, но с пометкой `debug`.
- **Отладочные забеги** (`?hero=…` и всё, что с ним) на Pages уходят с `debug = TRUE`; в сводках их отсекать фильтром.
- **Адрес не задан** (`STATS_URL` пустой) — не уходит ничего: форк или локальная сборка никуда не пишут.
- Ответ сервера игра не читает, ошибки сети глотает: статистика игре ничего не должна.

## Как подключить свою таблицу

Всё это делается в настольной версии Google: в мобильных приложениях Таблиц и Диска меню «Расширения» и редактора скриптов нет. С телефона — в браузере с включённой «Версией для ПК».

1. Создать Google Таблицу (имя любое). Лист `runs` и шапка появятся сами при первой записи.
2. Открыть редактор скриптов одним из двух способов:
   - в таблице **Расширения → Apps Script** — скрипт привязан к таблице, `SPREADSHEET_ID` оставить пустым;
   - или отдельно: https://script.google.com/home → **Новый проект**, а в `SPREADSHEET_ID` вписать id таблицы из её адреса (`docs.google.com/spreadsheets/d/<id>/edit`).
   Содержимое `Code.gs` заменить на `tools/apps-script/Code.gs` из репозитория, сохранить.
3. В панели редактора выбрать функцию `setup` и нажать **Выполнить**: скрипт спросит разрешения на таблицы (разрешить), в таблице появится лист `runs`, в журнале выполнения — её имя. Так проверяется id таблицы и снимаются разрешения до развёртывания.
4. **Начать развёртывание → Новое развёртывание**, тип **Веб-приложение**. «Запуск от имени» — **Я**, «У кого есть доступ» — **Все** (именно «Все», не «Все, у кого есть аккаунт Google»: игра шлёт без входа). Разрешить скрипту доступ к таблице, когда спросит.
5. Скопировать **URL веб-приложения** (оканчивается на `/exec`) и вставить в `STATS_URL` в `src/ui/telemetry.ts`. Адрес всё равно виден в собранном JS, прятать его незачем.

Таблицу при этом никому открывать не нужно: «Все» в развёртывании — это кто может прислать запись, а не кто видит таблицу. Скрипт работает от имени владельца и пишет в его частную таблицу; по адресу `/exec` посторонний получает только строку «приёмник на месте». Доступ к самой таблице стоит держать «Ограниченным» (кнопка «Настройки доступа»).
6. Закоммитить и запушить в `main` — Pages пересоберётся.

Если `setup` или запись падает с «Cannot read properties of null (reading 'getSheetByName')» — скрипт отдельный, а `SPREADSHEET_ID` пустой: впиши id таблицы (с версии со списком забегов скрипт пишет это прямо в ошибке).

Если окно развёртывания пишет «Не удалось открыть файл», почти всегда дело в нескольких аккаунтах Google в одном браузере: окно открывается под другим аккаунтом, у которого нет доступа к проекту. Лечится окном инкогнито на компьютере с входом только в тот аккаунт, где лежит таблица. Вторая причина — мобильный браузер в режиме «Версия для ПК» не справляется со всплывающими окнами; на компьютере это не воспроизводится.

## Как проверить

- Открыть адрес `/exec` в браузере: должно ответить «Monster Versus: приёмник статистики на месте».
- На Pages открыть `?hero=warrior&enter=1`, нажать `Esc` → «Бросить забег». В листе `runs` появится строка с `event = abandoned`, `debug = TRUE`.
- Гибель: `?hero=mage&loc=2&room=9&enter=1` — Маг первого уровня против финального босса; строка с `event = defeat` появляется сразу на плашке «Герой пал», до нажатия «К итогам».
- Локально то же самое с `&stats=1` в адресе (dev-сервер, `npm run dev`).

## Как обновить скрипт

Правка `Code.gs` в редакторе сама на адрес не попадает: **Развёртывание → Управление развёртываниями → карандаш → Версия: новая → Развернуть**. Адрес остаётся прежним. Новое поле в записи игры скрипт менять не требует: колонка добавится справа сама.

## Как смотреть

Фильтр `debug = FALSE`, дальше сводные таблицы: победы по `hero` и `version` (`event`), где гибнут (`location`, `room`, `lastBattle`), с чем доходят до конца (`weapon`, `artifacts`), сколько играют (`duration`). Строка `detail` разбирается любым JSON-просмотрщиком, если нужно заглянуть в конкретный забег.

## Ограничения

- Адрес публичный: кто угодно может дописать в таблицу что угодно. Скрипт проверяет только, что пришёл объект. Для хобби-игры терпимо; если начнётся мусор — переезд на Cloudflare Worker с проверкой формы, игровая часть при этом не меняется, только адрес.
- Квот Apps Script для нескольких сотен записей в день хватает с большим запасом; при одновременных записях скрипт берёт блокировку и пишет по одной.
- Ячейка вмещает 50 000 знаков — `detail` занимает единицы килобайт.

## Экран «Статистика» в игре (v0.32)

Кнопка в главном меню. Главные вкладки «Общее» и «Ты» в топбаре, каждая на весь кадр. «Общее» — сводка по всем игрокам: игра делает GET `STATS_URL?data=runs`, скрипт отдаёт `{keys, rows}` последних `RUNS_LIMIT` забегов без отладочных и без колонок `player`/`detail` (ответ кэшируется скриптом на `CACHE_SEC` и игрой в localStorage `mv_runs_v1` на 10 минут; кнопка «Повторить» идёт мимо кэша игры). Считает `src/engine/globalStats.ts`: законченные забеги и победы по героям, средний победный забег, урон, «Где гибнут» (клетка и убийца одной строкой), чем заканчивали забег (базы оружия и брони, артефакты — из колонок `weapon`, `armor`, `artifacts`). Внутри вкладки «Герои / Гибели / Убийцы / Оружие / Броня / Артефакты». «Ты» — своя статистика из профиля, она работает и без сети. Проверить экран без таблицы: `?screen=stats&mock=1`.
