# Monster Versus — краткий контекст для LLM

База: `main`, коммит `33e2de5` от 2026-09-20. Локальное обновление 2026-09-21: рисованные скелеты воин и лучник и некромант с семью анимациями, `GAME_VERSION = 0.41.16`, `SAVE_VERSION = 31`. Обновление 2026-09-25 (v0.52.6): рисованные листы врагов убраны, все враги — пиксельная лепка `src/ui/mobs/`. При дальнейших изменениях сверять с кодом и `CLAUDE.md`.

## Что за проект

- Браузерный пошаговый рогалик: 6 героев, 3 акта по 10 комнат; локации выбираются из 6. Бои с видимыми намерениями врагов, события, торговец, награды и боссы.
- Билд собирается из оружия и брони с сокетами для артефактов; ресурсы — HP, STA, MP. Есть зелья, статусы, призывы, дальность атак и владение типами снаряжения.
- TypeScript strict + Vite + обычные DOM/CSS, без UI-фреймворка и игрового движка. Тесты — Vitest. Тексты игры, комментарии и документация — на русском.
- Игра работает как статика. Сохранения — `localStorage`. Отдельная интеграция статистики — Google Apps Script; адрес уже задан в `src/ui/telemetry.ts`, локальные забеги по умолчанию не отправляются.

## Механики: важные связи

- `engine` не зависит от DOM, но изменяет переданное состояние на месте. Игровые правила должны оставаться здесь, экран вызывает их через `App`. Поток: `newRun → enterRoom → бой/событие → награда → advanceRoom`.
- Сначала искать нужное число в `data`, затем обработчик в `engine`. Новый эффект требует согласовать тип `Effect`, исполнение в `combat.ts`, расчёт статов/описаний и отображение; одного изменения карточки недостаточно.
- Новый враг: определение в `enemies.ts`, встречи в `locations.ts`, спрайт. Новый артефакт: `artifacts.ts`, тип сокета, при необходимости веса дропа в `loot.ts` и оценка в `tests/sim/bot.ts`. Коллекция собирается из таблиц автоматически.
- Случайность боя и мира использует общий `run.rng` из `rng.ts`. Одинаковый сид воспроизводит результат при одинаковых исходных условиях и действиях; лишний бросок меняет последующие награды и встречи. Предпросмотр не должен расходовать настоящий RNG.
- При изменении структуры сохраняемого состояния обновлять `SAVE_VERSION`: несовместимый забег перестанет загружаться. Профиль с коллекцией/победами хранится отдельно и переживает смену версии. `GAME_VERSION` — отдельная строка версии в меню.
- Изменения баланса оценивать симуляцией до/после; для персональных артефактов проверять оба варианта. Поведение бота не заменяет проверку живой игры.

## Дизайн и интерфейс

- Логический кадр **960×540**, масштабируется целиком в `src/main.ts: fit()`. Это фиксированная раскладка, не мобильная перевёрстка. Каркас забега: топбар **40**, центр **320**, консоль **180 px**.
- Палитра — CSS-переменные в начале `style.css`. Основной шрифт Handjet, заголовки Tiny5. Небольшие изменения высоты могут обрезать содержимое: у кадра `overflow: hidden`.
- Экран — функция `xxxScreen(app): HTMLElement`, элементы создаются через `h()`/`button()` из `dom.ts`. `App.render()` заменяет дерево; `commit()` сохраняет забег и перерисовывает. Состояние оверлеев хранится в `App`.
- Наведение и прицел обновляют готовые DOM-узлы без полной перерисовки. Подсказки задавать через `tip`/`tipTitle`, описания — через `markKeywords()`. Недоступным боевым плиткам нужен класс `off` и проверка клика: `disabled` мешает показывать причину при наведении.
- В бою HP/блок врагов находятся над спрайтом, имя — снизу. `.field` задаёт общую линию стоп через высоту подписи и нижний отступ; прозрачные поля canvas скелетов исключены из раскладки отрицательными отступами только внутри `.enemy.drawn`.
- Управление централизовано в `hotkeys.ts`: цифры — приёмы, Tab/Enter — цель/применение, Space — конец хода, C — персонаж, L — лог, Esc — верхний слой/пауза.

## Анимации и графика

- Единая шкала роста: `src/data/characterSizes.ts` задаёт видимый рост тела всех врагов и героев. `src/ui/characterSize.ts` переводит его в размер атласа, отдельно учитывая оружие и прозрачные поля; `spriteBounds` измеряет процедурные фигуры. Скелеты 100, некромант 120, воин 128; диапазон врагов 36–184. Союзники используют ту же шкалу, бестиарий — пропорциональное уменьшение. Размер не зависит от ранга или наличия союзников. Предпросмотр смешанных групп: `/tools/character-size-preview.html`.

- Враги (v0.52–v0.52.6): у всех 71 — пиксельная лепка кодом (`src/ui/mobs/<локация>.ts`), три клипа: покой, удар (контакт на 333 мс — к нему `App.step()` приурочивает снаряд и цифру) и урон. Рисованные листы скелетов и некроманта (v0.41.7–v0.41.13) убраны в v0.52.6 вместе с `necromancerFrames.ts`, `tools/enemy-sheet.sh` и мастерами; процедурный спрайт `sprites.ts` остался запасным.

- `heroSprite.ts`: `HERO_SHEETS` задаёт лист, порядок клипов, `frames`, `cell`, `body`; `CLIP_MS` — длительности, `FALLBACK` — замены отсутствующих клипов. В ряду **8 кадров**, CSS листает их через `steps()`.
- Сейчас боевые клипы есть у **Воина и Мага**. Ассасин, Паладин, Берсерк и Лучник имеют только `idle`; действия используют типовой наскок. Мастер `art/paladin-anim.png` сохранён, но его боевые клипы отключены в текущей версии.
- Последовательность: `planHeroFx/planEnemyFx` собирает план до изменения состояния → движок применяет действие → `playShots` показывает полёт на старом поле → при попадании UI перерисовывается и показывает последствия. Не переносить расчёт боя в анимационные таймеры.
- Перерисовка переносит живой `.fx-layer`, клип героя продолжается с прошедшей позиции. При смене таймингов учитывать `FLIGHT`, `HIT_GAP`, многоударные атаки, полоски HP, `busy`/таймеры в `App`; иначе визуал рассинхронизируется с состоянием.
- Конвейер: **мастер `art/` → скрипт `tools/` → файл `src/assets/` → регистрация в таблице UI**. Герои — `hero-sheet.py`, портреты — `hero-avatars.py`, фоны — `location-bg.py`. Значения `cell/body` брать из вывода скрипта.
- Герои/портреты используют `image-rendering: auto`, процедурные спрайты и фоны — `pixelated`. Фоны `wide/tall` — оба **960×320**, портреты **256×256**. Свет локаций задаёт `TINTS` в `tint.ts`; ассеты прогревает `preload.ts`.
- Полные требования к стилю, мастерам, выравниванию и сжатию — в `docs/art.md`. Правка только готового PNG потеряется при пересборке из мастера.

## Запуск и проверка изменений

Node.js 22 используется в CI. Из корня проекта:

```bash
npm ci
npm run dev
node node_modules/typescript/bin/tsc --noEmit -p .
npm test
npm run build
# При правках баланса — до и после, на одинаковых параметрах:
SIM=1 SIM_N=300 npx vitest run tests/balance-sim.test.ts
SIM=1 SIM_SIG=2 SIM_N=300 npx vitest run tests/balance-sim.test.ts
```

Обычный `npm test` пропускает длительные SIM-тесты. Регрессии механик добавлять в соответствующие `tests/*.test.ts`; дизайн и анимации проверять в браузере, включая переполнение, наведение и переходы. Для UI полезны адреса относительно `http://localhost:5173/`:

```text
?hero=warrior&seed=5&enter=1
?hero=warrior&art=whirlwind,stun_strike,war_cry,second_wind,bleed_cut,fireball&enter=1
?hero=mage&art=wolf_whistle&use=wolf_whistle&enter=1
?hero=warrior&phase=reward&focus=attack
?hero=warrior&phase=event&event=forge
?hero=warrior&locs=crypt,forest,ship&room=9&enter=1&boss2=1
```

Также проверять `phase=shop|camp`, `sheet=1`, `pause=1`; `tint=off` отключает свет. В консоли: `mv.run`, `mv.render()`. Отладку проводить в отдельном профиле/контексте браузера: `mock=1` записывает демо-профиль, а `render()` может обновлять коллекцию и статистику. Пуш в `main` запускает тесты, сборку и публикацию GitHub Pages.
